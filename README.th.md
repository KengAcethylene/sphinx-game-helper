# sphinx-game-helper

ตัวช่วยทาย Sphinx ของ TalesRunner ด้วย binary search (ช่วงตัวเลข 1–9999, ทายได้สูงสุด 14 ครั้งต่อรอบ)

[English](README.md) · ภาษาไทย

**เล่นได้ที่**: <https://kengacethylene.github.io/sphinx-game-helper/>

## วิธีเปิดใช้งาน

เข้าผ่าน URL ด้านบน หรือดับเบิลคลิก `index.html` เพื่อเปิดในเครื่อง

## วิธีใช้

1. ตัวเลขใหญ่ตรงกลางคือเลขที่ควรทาย (binary-search ที่เหมาะสมที่สุด) — พิมพ์เลขนั้นลงในเกม
2. กดปุ่มตามผลที่เกมตอบกลับ:
   - **Lower** — คำตอบจริงน้อยกว่าเลขที่ทาย
   - **Correct** — ทายถูก (จะบันทึกประวัติและรีเซ็ตอัตโนมัติใน 3 วินาที)
   - **Higher** — คำตอบจริงมากกว่าเลขที่ทาย
3. ตัวเลขใหม่จะอัปเดตอัตโนมัติ

## พิมพ์เลขเอง

คลิกที่ตัวเลขใหญ่เพื่อแก้ไขได้ มีประโยชน์เวลาอยากลองเลขนำโชค (เช่น 1004, 7777) ในการทายครั้งแรก ๆ คลิกที่ pill ด้านล่างเพื่อกลับไปใช้เลขที่ binary-search แนะนำ

## โหมด Jitter

ตัวเลือกเสริมที่ toggle ได้ด้านล่างของหน้า เมื่อเปิด จะสุ่ม offset ±3% ของช่วงปัจจุบันใส่ในเลขแนะนำสำหรับ 5 ครั้งแรก เพื่อให้แต่ละรอบเดินทางต่างกันแทนที่จะวนไป 5000 → 2500/7500 → … ทุกครั้ง ข้อเสียคือเพิ่มโอกาสทายไม่ทันใน 14 ครั้งเล็กน้อย แต่รูปแบบการทายจะดูซ้ำน้อยลง การตั้งค่าจะถูกจำไว้ข้ามเซสชัน

## ปุ่มลัดคีย์บอร์ด

(ใช้ได้เมื่อช่องตัวเลขไม่ได้ถูก focus อยู่)

| ปุ่ม | ทำงาน |
|---|---|
| `J` / `←` | Lower |
| `K` | Correct |
| `L` / `→` | Higher |
| `R` | รีเซ็ตรอบ |
| `Enter` (ในช่อง input) | ส่งเป็น Correct |
| `Esc` (ในช่อง input) | ออกจากช่อง input |

## ประวัติคำตอบ

ทุกครั้งที่ทายถูก จะบันทึกลง `localStorage` พร้อม timestamp, คำตอบ, และจำนวนครั้งที่ใช้ ดูได้ที่หัวข้อ "Past Wins" ด้านล่างของหน้า ปุ่ม **Export CSV** ดาวน์โหลดประวัติทั้งหมดเป็นไฟล์ CSV สำหรับวิเคราะห์ต่อ (เช่น เช็คว่าคำตอบกระจายตัวสุ่มจริงไหม)

## บันทึกสถานะรอบปัจจุบัน

สถานะรอบที่กำลังเล่นอยู่ (ช่วง, ประวัติ, จำนวนครั้งที่ทาย) จะถูกบันทึกลง `localStorage` ทุกครั้งที่กดปุ่ม และจะโหลดกลับมาเมื่อรีเฟรชหน้า — เผลอปิดแท็บหรือ refresh กลางรอบก็ไม่หาย กด **Reset** (หรือ `R`) เพื่อเริ่มรอบใหม่

## หมายเหตุเชิงกลยุทธ์

- กรณีแย่ที่สุด: 14 ครั้ง (ขอบเขตขั้นต่ำตามทฤษฎีสารสนเทศสำหรับเลข 9999 ตัว)
- ค่าเฉลี่ยด้วย binary search: ~12.3 ครั้ง เมื่อคำตอบสุ่มแบบ uniform
- ถ้าคำตอบสุ่มจริง ๆ จะไม่มีทางเอาชนะค่าเฉลี่ยนี้ได้ — กลยุทธ์เดียวคือเล่นเยอะ และมองรอบที่จบเร็วเป็นเหมือนการลุ้นรางวัล
- ต่อรอบ: P(จบใน ≤ k ครั้ง) = (2ᵏ − 1) / 9999 รอบที่จบใน ≤7 ครั้งเกิดประมาณ 1.3% ของทุกรอบ

### โควตารายวัน

ทุกวันได้ key จาก daily quest 50 ดอก → **เล่นได้สูงสุด 50 รอบต่อวัน** ตลอด 50 รอบนี้:

| มีรอบที่จบใน ≤ k ครั้ง อย่างน้อย 1 รอบ | ความน่าจะเป็นต่อวัน |
|---|---|
| ≤ 4 (รางวัลสูงสุด) | ~7% (≈ ทุก ๆ 2 สัปดาห์) |
| ≤ 7 (รางวัลระดับดี) | ~47% (เกือบทุกวันเว้นวัน) |
| ≤ 10 | ~99.5% (เกือบทุกวัน) |

สูตร: `P = 1 − (1 − (2ᵏ−1)/9999)⁵⁰` เล่นให้ครบ 50 key ทุกวัน เดี๋ยว variance ทำงานเอง
